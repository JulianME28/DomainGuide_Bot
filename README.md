# DomainGuide Bot

Telegram-бот для аналізу донорських баз під SEO / linkbuilding.

Читає Google Таблицю в режимі «тільки перегляд» і відповідає на питання
на кшталт «скільки в нас донорів по Німеччині з трафіком від 100».
Повертає **виключно зведені показники**: кількість, середній DR, середній
трафік, розподіли й рекомендації. Повний список донорів і самі домени не
видаються ніколи.

---

## ⚠️ Два кроки, без яких бот не запрацює

### 1. Вписати токен бота

Відкрийте файл `.env` і впишіть токен у порожній рядок:

```
BOT_TOKEN=
```

Де взяти: у Telegram напишіть боту **@BotFather** → команда `/newbot` →
придумайте ім'я → скопіюйте видане значення (виглядає як
`1234567890:AAF...`) і вставте одразу після знака `=`, без пробілів.

**Більше в `.env` міняти нічого не треба** — решта вже заповнена.

### 2. Поділитися таблицею з ботом

Зараз Google **не пускає** бота до таблиці — я це перевірив, він відповідає
помилкою 403. Таблицею треба поділитися, як з людиною:

1. відкрийте таблицю в Google Таблицях;
2. натисніть **«Поділитися»**;
3. додайте цю адресу:

   ```
   domainguide-bot@domainguide.iam.gserviceaccount.com
   ```

4. рівень доступу — **«Переглядач»**, зберегти.

Це адреса сервіс-акаунта з файлу `credentials.json`. Доступ на перегляд —
максимум, що бот технічно може отримати: він працює зі scope
`spreadsheets.readonly` і змінити щось у таблиці не здатен за визначенням.

Поки цього не зроблено, бот **запуститься й працюватиме**, але на кожен
запит чесно відповідатиме, що база недоступна, і показуватиме цю ж
інструкцію.

## Як користуватися

Напишіть боту `/start` — далі все кнопками.

**Кнопками:** база → країна (або мова, або зона) → результат.
Для складних запитів є **🧙 Майстер-запит**: країна → трафік → DR → резюме →
запуск. На кожному кроці є «Назад», «Скинути» і «До меню».

**Текстом** — теж працює:

```
Меджик, Британія, трафік від 1, DR не важливий
скільки німецькомовних донорів з DR від 20
Морди, .de, трафік від 100
```

**Команди:** `/start` `/help` `/magic` `/mordy` `/submits` `/query` `/ai` `/chat`
`/filters` `/reset` `/admin`

**🧠 Індивідуальний запит** (`/ai`) — ШІ перетворює стандартну чи нестандартну
умову на безпечний фільтр/операцію, а за нестачі параметрів просить уточнення.
Якщо базу не названо, результат показується по всіх доступних базах; явна назва звужує запит до однієї.
Фраза «окремо» дозволяє порівняти до 6 незалежних критеріїв в одному запиті.
Несумісні межі нашталт `DR від 50 і до 20` також автоматично рахуються як два окремі зрізи.

**💬 ШІ-консультант** (`/chat`) — живий діалог з пам’яттю останніх реплік: пояснення,
порівняння, стратегії та рекомендації. Консультант не бачить базу і не вигадує чисел.

## Головне про цифри: країна і мова — це різні речі

**У даних немає колонки країни.** Її не існує і не планується. Тому країна
визначається за **доменною зоною**: сайт у зоні `.de` вважається німецьким.

Через це на питання «скільки донорів по Німеччині» є **дві різні відповіді**:

| | що це |
| --- | --- |
| **6 донорів у зоні `.de`** | сайти з німецьким доменом |
| **+4 донори німецькою мовою поза зоною `.de`** | сайти німецькою в інших зонах |

Бот показує перше число як основне, а друге — **окремим останнім рядком**
зі значком 💬 і словами «поза зоною».

> ### ⚠️ Ці два числа не можна складати
>
> 6 + 4 = 10 було б неправильно. Частина донорів одночасно і в зоні `.de`,
> і німецькою мовою — у сумі їх порахували б двічі. Тому мовний рядок
> навмисно стоїть окремо: це відповідь на **інше питання**, а не друга
> половина першої.

Бот сам стежить, щоб подвійного рахунку не було: у мовний рядок потрапляють
лише ті донори, яких **немає** в зоновому наборі.

**Про спільні мови.** Англійською, іспанською, португальською та арабською
пишуть у багатьох країнах. Для них бот додає попередження:
«англійською пишуть багато країн, не лише Британія». Для однозначних мов
(французька, німецька) попередження немає — воно було б зайвим шумом.

**Глобальні зони** (`.com`, `.net`, `.org`, `.online`, `.co` …) не належать
жодній країні. Бот ніколи не приписує їх якійсь державі — інакше цифри були
б вигаданими.

## Безпека

- **Секрети тільки в `.env`.** У коді немає жодного токена, ID чи списку
  користувачів. `.env`, `credentials.json` і взагалі всі `*.json` внесені
  в `.gitignore` **до першого коміту** — ключ не потрапляв в історію git
  жодного разу.
- **Доступ за списком.** Бот не відповідає нікому, крім `ALLOWED_USER_IDS`.
  Стороннім він мовчить, а не пише «вам не можна».
- **Тільки перегляд.** Scope `spreadsheets.readonly` — змінити щось у
  таблиці бот не здатен технічно.
- **Whitelist колонок.** Бот запитує в Google лише дозволені стовпчики.
  Дані з інших колонок не просто не зберігаються — вони навіть не залишають
  сервер Google.
- **Домени не витікають.** Домен — службове поле для визначення зони. Він
  не показується й не пишеться в лог. Це забезпечено будовою: шар підрахунків
  повертає об'єкт, у якому списку донорів фізично немає, тому показувати
  просто нічого. Окремі тести перевіряють, що жоден домен із бази не
  трапляється у відповіді.
- **Ліміт запитів** на користувача — захищає бота й квоту Google.
- **Бот не падає.** Немає інтернету, впав Google, битий рядок у таблиці,
  порожній аркуш — усе це нормальні ситуації з чесним повідомленням.

## Перевірка коду

```powershell
.venv\Scripts\python.exe -m pytest          # 540 тестів
.venv\Scripts\python.exe -m ruff check .    # перевірка стилю
.venv\Scripts\python.exe -m ruff format .   # автоформатування
```

Тести працюють на вигаданих даних — без інтернету, без ключа Google і без
справжньої таблиці. Запускати їх можна будь-коли й скільки завгодно.

## Якщо щось не працює

| Симптом | Причина й що робити |
| --- | --- |
| «У файлі .env не заповнено BOT_TOKEN» | впишіть токен від @BotFather |
| «Google не дав доступ (403)» | поділіться таблицею з `domainguide-bot@domainguide.iam.gserviceaccount.com` |
| Бот мовчить на всі повідомлення | вашого Telegram ID немає в `ALLOWED_USER_IDS` |
| «У таблиці немає аркуша …» | назва аркуша в `config/columns.toml` не збігається з реальною (важливі регістр і мова літер) |
| «Немає колонки …» | колонку перейменували — виправте `config/columns.toml` |
| Цифри застаріли | адмінка → «🔄 Оновити дані» |
| «Морди: 0 донорів» | аркуш справді порожній, це не помилка |
